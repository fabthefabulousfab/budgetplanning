# Projet démo depuis l'accueil — plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. TDD, small commits.

**Goal:** Depuis la page d'accueil, un bouton « Découvrir avec un exemple » ouvre l'application remplie de données fictives, entièrement en mémoire.

**Décidé avec le PO :**
- Démo en mémoire : rien n'est écrit sur l'ordinateur ; on peut tout modifier pour essayer ; tout est perdu à la fermeture/au rechargement.
- Bandeau toujours visible : « Mode démo : données fictives, rien n'est enregistré » + bouton « Quitter la démo » (retour à l'accueil, état remis à zéro).
- Proposée aussi dans les navigateurs sans accès aux dossiers (Safari, Firefox) : l'écran « Navigateur non pris en charge » garde son message et ajoute le bouton de démo.

**Architecture :**
- `js/demo.js` (nouveau, module classic-script) : `DEMO_FICHIERS` = contenu YAML des 4 fichiers (`donnees-courantes.yaml`, `evenements-futurs.yaml`, `parametres.yaml`, `paliers.yaml`) ; `dossierDemo(maintenant) -> DirHandle` en mémoire respectant le seam (`getFileHandle(nom,{create})` → `{getFile(), createWritable()}`, NotFoundError si absent) ; `depart` de parametres = mois courant (dates des lignes/événements calculées relativement à `maintenant` pour rester crédibles quel que soit le jour d'ouverture).
- Données fictives d'une famille type (aucune donnée réelle, ne jamais lire les fichiers de données de l'utilisateur) : 2 salaires avec taux de revalorisation propres, allocations, loyer/crédit immobilier, courses, transport, abonnements, assurances, impôts, loisirs ; annuel (taxe foncière, vacances, prime) ; un exceptionnel ; événements futurs (naissance/études ou achat voiture) ; un prêt (`nature: pret`) ; au moins un palier ; une ligne masquée ; catégories = liste par défaut (`CATEGORIES_DEFAUT`) ; inflation 2 %. Les chiffres donnent un solde positif mais avec un mois tendu visible sur le graphe.
- `js/ui-app.js` : `ouvrirDemo()` → `start(dossierDemo(new Date()), { demo: true })` (ou équivalent) ; `state.demo = true` ; bandeau (`role="status"`, classes du thème, pas d'hex) ; « Quitter la démo » remet l'état à zéro et réaffiche `ecranAccueil()`. En démo : la persistance écrit dans le dossier mémoire (le flux normal reste inchangé), l'export/import de sauvegarde dans Paramètres est désactivé avec une phrase d'explication, l'historique CSV n'est pas écrit sur disque (il l'est dans le dossier mémoire seulement). Tout accès à `showDirectoryPicker` est évité en démo.
- Visite guidée : texte de l'accueil mentionnant le bouton démo (`data-aide="accueil-demo"`) ; la visite fonctionne dans la démo. README : section courte « Démo ».

## Global Constraints
- Classic-script modules, `index.html` charge `js/demo.js` ; publication `scripts/publier-pages.sh` inclut `js/*.js` automatiquement.
- Aucun hex dans `css/style.css`, contrastes AA clair/sombre, `prefers-reduced-motion`, impression (bandeau masqué à l'impression).
- Tests `node --test tests/js/` et `uv run pytest tests/py -q` verts (baseline 318 / 34).

## Review Focus
1. Les données de démo passent `loadAll` strictement (test) et donnent une projection sans NaN sur tout l'horizon.
2. Aucune écriture hors mémoire en démo (test sur le seam + vérification qu'aucun `showDirectoryPicker` n'est appelé).
3. Quitter la démo puis ouvrir un vrai dossier : aucun reste d'état démo (bandeau, données, `state.demo`).
4. Safari/Firefox (pas de `showDirectoryPicker`) : la démo s'ouvre et fonctionne ; les fonctions dossier restent indisponibles.
5. Rechargement en démo : retour à l'accueil, rien de persistant (pas de localStorage).
